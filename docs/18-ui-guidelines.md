## 共通(画面階層とナビゲーション)

全画面で「今どこにいるか」「どこへ戻れるか」を揃える。規則の本文は`.claude/skills/ui-interaction-patterns`の
§2.26(画面階層と戻る導線)にあり、ここには要点だけを書く。

- 画面名と親画面は`frontend/src/routes/pageHierarchy.ts`の1か所で定義する。
- 第2階層以下の画面は左上に「〈 {戻り先}に戻る」(`BackLink`)を1つ置く。パンくずリストは置かない。
- 戻り先は、来た画面(一覧の絞り込み・ページを含む)を優先し、URLを直接開いた場合は親画面にする。
- キャンセル・削除後の遷移先は戻る導線と同じ。
- サイドバーは表示中の画面が属する項目を点灯させ、ブラウザのタブ名は`{画面名} | flow-office`にする。
- 一覧画面の検索フォーム(主軸タブ・フィルターバー・反映方式・クリア)は`.claude/skills/ui-interaction-patterns`の§2.20に従う。

## 一覧・見出しのレイアウト

規則の本文は`.claude/skills/ui-interaction-patterns`の§2.1・§2.17・§2.20・§2.27にあり、ここには要点だけを書く(変更セット`20261123-list-layout-standard`)。

- 管理画面(`/admin`配下)は、本文の先頭に見出し(画面名)と説明文を置く(`PageHeader`)。見出しは`pageHierarchy.ts`の画面名と同じ。
  管理画面以外はページ見出しを置かず、主となるCardの見出しが画面名になる。
- 管理メニュー(縦のサイドバー)は幅1280px(`xl`)以上だけに出し、未満はメニューボタンで開く(アプリのサイドバーと並んで本文が狭くなるのを避ける)。
- 一覧の主操作は「新規作成」(業務用語の「新規申請」「新規登録」は例外)で、管理画面は見出しの右、管理画面以外は主となるCardの右上に置く。
- 狭い幅では、主軸タブは折り返し、表は横スクロールのまま自由入力の長い列だけ折り返す。

### 画面ごとに個別に判断する課題(2026-11-24 ユーザー判断)

次は画面ごとに事情が違うため、まとめて対応せず、その画面を見直すときに個別に判断する。

- 上の複数機能の画面の分割。
- Dialog で行っている大きな作業をページに移すこと(§2.11)。対象は勤務形態の作成・編集、所属変更の予約、ロールの作成、有給の付与表の新バージョン。
- 一覧の中に埋め込んだ作成フォーム(インライン)をページか Dialog に移すこと。並べ方の標準化もそのときに行う。対象は社員一覧・端末・外部連携設定・API・MCP連携・グループ種別・有給の付与ルール・採番ルール。

### Enter キーでの送信(2026-11-24 ユーザー判断)

- データを変更するフォーム(作成・編集・申請・設定)では、誤送信を防ぐため Enter キーで送信しない。送信はボタンだけで行う。
- ログインのように確定して進むフォームは、Enter キーで送信できるようにする。
- 一覧の検索欄は入力で自動的に絞り込むため(ボタン無し)、対象外。
