# e2e(scenario-03)の有給申請の再試行で、前の対象日が残って失敗し続ける不具合の修正

ステータス: 完了

## 変更要望(原文)

```
終わったらe2eも実施してください
```

(e2eの全件実行で`scenario-03`「半休を申請〜承認し、勤怠日に反映される」が失敗した。原因を調べたところ、e2eの補助処理の不具合だった。)

## 背景・目的

scenario-00〜02の後にscenario-03を流すと、半休の申請が「有給申請に20回試行しても成功しなかった」で失敗する(単独では通る)。e2eを安定させる。

## 現状(As-Is)

- `frontend/e2e/scenario-03-paid-leave.spec.ts`の`submitPaidLeaveRequest`(61〜96行):来月の勤務日をランダムに選び(`randomWorkingDate`)、対象日・取得単位・承認者を
  入力して申請する。「この日は既に有給を申請済みです。」なら別の日で再試行する。ページを開き直さずに、同じフォームで再試行する。
- 有給の申請フォームの対象日は複数の日を選べる欄で、`pickDate`で選ぶたびに日が追加される。
- 失敗時の画面:エラー「全休の日には他の休暇を併存できません。」が出ており、対象日の欄に5日分が残っていた。

## 設計前提の検証

- 原因:ランダムに選んだ日が、先行のシナリオで作られた全休と同じ日になると申請が拒否される(業務ルールどおり)。再試行では前の日が残ったまま日が追加されるため、
  拒否された日が入ったまま以降の申請がすべて失敗する。待っているエラーの文言も「既に有給を申請済み」だけで、「併存できません」は待たずに30秒のタイムアウトまで待つ。
- 前回の全件実行で通ったのは、たまたま全休と重ならなかったため。今回の変更(申請一覧のページング等)とは無関係(失敗時の申請一覧は1ページに収まっていた)。
- 原因の分類:e2eの手順のミス。

## 仕様検討

### 論点1: 直し方
- 選択肢:
  - A. 再試行のたびに`/paid-leave`を開き直し、フォームを空に戻してから入力する。拒否のエラーは文言を限らず、申請フォームのエラー(`role="alert"`)が出たら拒否とみなす。
  - B. 選んだ日のチップを削除してから次の日を選ぶ。フォームの作りに強く依存する。
- 決定: A
- 理由: フォームの状態を確実に初期化でき、拒否の理由(重複・併存不可など)が増えても再試行できる。
- 未確定・要確認事項: なし

## 仕様確定事項(まとめ)

- `submitPaidLeaveRequest`:各試行の最初に`await page.goto('/paid-leave')`と、読み込みの完了待ち(`await expect(page.getByText('読み込み中...')).toHaveCount(0)`)を行う。
  結果の判定は「申請中の行が出た」または「申請フォームのエラー(`page.getByRole('alert')`)が出た」の早い方とし、エラーなら次の試行へ進む。待ち時間は各15秒。
  関数のdocコメントを直す(呼び出し前に`/paid-leave`を開いておく前提は不要になる)。
- 同じファイルの他の処理は変えない。
