# 戻るリンクは「掘り下げ」で開いた画面にだけ出す(日次・週次・月次勤怠の戻る導線)

- ステータス: レビュー中
- 種別: 仕様変更(frontend・UIガイドライン)

## 変更要望(原文)

> 日次勤怠については週次・月次から遷移した場合のみ戻れるようにしてください。メニューから遷移した場合は戻るリンクは不要です。
> 日次勤怠から週次勤怠を押下した場合や、週次から月次勤怠を押下した場合も戻るリンクは不要です。
> 感覚なのですが、言語化されたルールを考えてください。

## 背景・目的

変更セット`20261121-navigation-hierarchy`で「画面内から別の画面へ進むリンクは、進む先の階層に関わらず遷移元を記録する」
(`ui-interaction-patterns` §2.26-3)とし、記録が無ければ階層上の親へ戻るリンクを出すようにした。その結果、
「週次 →(月次勤怠ボタン)→ 月次」で「週次勤怠に戻る」、メニューから開いた日次で「11月の勤怠に戻る」が出る。
利用者の感覚では、これらは「戻る」場面ではない。この感覚を規則として言語化し、ガイドラインと実装を揃える。

## 現状(As-Is)

- `frontend/src/navigation/backState.ts` `useBackTarget`: 戻り先 = 記録された遷移元 → `pageHierarchy`の親 の順。
- `frontend/src/routes/pageHierarchy.ts`: `/attendance/days/:date`の親 = `/attendance/months/<年月>`、
  `/attendance/months/:yearMonth`の親 = `/attendance/months`(月の一覧)。週次は第1階層(親なし)。
- サイドバー(`routes/routeManifest.ts`): 日次 → `/attendance/days/<今日>`、週次 → `/attendance/week`、
  月次 → `/attendance/months/<今月>`(月の一覧`/attendance/months`はサイドバーに無く、月次画面の「月次勤怠に戻る」からだけ開ける)。
- 遷移元を記録しているリンク(勤怠):
  - 日次 →「週次」(`pages/attendance/AttendanceDayPage.tsx:1311`)
  - 週次 →「月次勤怠」(`pages/attendance/WeekAttendancePage.tsx:182`)
  - 月次の週の警告 →「週次勤怠で振り分ける」(`pages/attendance/AttendanceMonthDetailPage.tsx:276`)
- 週次画面には戻るリンク(`BackLink`)が無い(第1階層のため)。
  - 週次・月次の日の行 → 日次(`components/AttendanceDayRow/AttendanceDayRow.tsx:127`)
  - ホームの今日の勤怠 →「日次勤怠」(`components/TodayAttendancePanel/TodayAttendancePanel.tsx:188`)
  - 月の一覧の行 → 月次(`pages/attendance/AttendanceMonthsPage.tsx:125`)

## 設計前提の検証

- 原因の分類: 規則の誤り。「進む遷移はすべて遷移元を記録する」「記録が無ければ親へ」の2点が粗く、
  「切り替え」と「掘り下げ」を区別していなかった。

## 仕様検討

### 論点1: 言語化した規則

**戻るリンクは「掘り下げて開いた画面」にだけ出す。** 遷移を次の3種類に分けて扱う。

| 遷移の種類 | 判定 | 例 | 戻るリンク |
|---|---|---|---|
| **掘り下げ** | 遷移元の画面に表示されている**1件**(一覧の行・集計の内訳・警告やお知らせのカード・参照先)を選んで**その1件**を開く。または、遷移元の対象の**付属画面**(履歴・編集・作成)を開く。遷移先は遷移元の**中にあるもの**。 | 週次・月次の日の行 → 日次、月次の週の警告 → その週の週次、月の一覧 → ○年○月、申請一覧 → 申請詳細、ホームの「今日の勤怠」→ 日次、有給 →「履歴」 | 出す(遷移元へ戻る) |
| **切り替え** | 見る単位・見る場所を替える。遷移先は遷移元を**含む全体**か、**並列の別の画面**。メニュー・ヘッダからの移動もこれ。 | メニュー → 日次、日次 →「週次」(その日を含む週)、週次 →「月次勤怠」(その週を含む月) | 出さない(それまでの戻り先も捨てる) |
| **横移動** | 同じ単位の隣へ動く。 | 前日/翌日/今日、前月/翌月/今月、画面内タブ・絞り込み | 掘り下げで来ていれば、その戻り先をそのまま保つ |

迷ったときの問い: **「遷移先は、遷移元の画面の中にあるもの(表示されていた1件、またはその画面の対象の付属画面)か?」** はい → 掘り下げ、いいえ(全体・並列の画面)→ 切り替え。
同じ画面(例: 週次)でも、どう来たかで扱いが変わる: メニューから来れば切り替え、月次の週の警告から来れば掘り下げ。

直接開いた場合(URL・再読込・新規タブ・共有リンク)の扱い:

- **メニューから開ける画面**(日次・週次・月次などサイドバーの行き先): 戻るリンクを出さない(メニューから開いたのと同じに扱う)。
- **単独では成り立たない画面**(申請詳細・経費の編集・有給履歴など、親の中の1件・付属の画面): 階層上の親へ戻る(現行どおり)。

### 論点2: 勤怠画面への当てはめ

| 遷移 | 種類 | 遷移先の戻るリンク |
|---|---|---|
| メニュー → 日次 / 週次 / 月次 | 切り替え | なし |
| 週次の日の行 → 日次 | 掘り下げ | 「週次勤怠に戻る」 |
| 月次の日の行 → 日次 | 掘り下げ | 「○年○月の勤怠に戻る」 |
| ホームの「日次勤怠」→ 日次 | 掘り下げ(今日の1件) | 「ホームに戻る」 |
| 日次 →「週次」 | 切り替え | なし |
| 週次 →「月次勤怠」 | 切り替え | なし |
| 月次の週の警告「週次勤怠で振り分ける」→ 週次 | 掘り下げ(その週の1件) | 「○年○月の勤怠に戻る」(週次に戻るリンクを新設) |
| 月の一覧 → ○年○月 | 掘り下げ | 「月次勤怠に戻る」 |
| 日次の前日/翌日/今日、月次の前月/翌月/今月 | 横移動 | 来たときの戻るリンクを保つ |
| 日次・月次をURLで直接開く | (メニューから開ける画面) | なし |

### 論点3: 月の一覧への導線

- 月の一覧(`/attendance/months`)は、いまは月次画面の「月次勤怠に戻る」(親へのフォールバック)からしか開けない。
  論点1の規則で月次の戻るリンクが消えると、月の一覧へ行けなくなる。
- 選択肢: A. 月次画面の月送り(前月/今月/翌月)の並びに「月の一覧」リンクを置く。B. 月の一覧をサイドバーに足す。
- **決定: A。** 戻るリンクが出ている(月の一覧から掘り下げて来た)ときは重複するため出さない。
  月の一覧はメニュー項目を増やすほどの頻度ではないため、Bは採らない。

### 論点4: 他ドメインの既存リンクへの当てはめ

- 規則はガイドライン(§2.26)として全画面に適用する。遷移元を記録しているリンクは約65か所(29ファイル)あり、
  一覧を「点検結果」に載せ、**切り替え**に当たるものだけ遷移元の記録を外す。

## 仕様確定事項(まとめ)

1. `ui-interaction-patterns` §2.26 を論点1の規則に書き換える(「進む先の階層に関わらず`useForwardState`を渡す」を、
   「掘り下げのリンクだけ`useForwardState`、切り替えのリンクは`state`を渡さない、横移動は`useKeepBackState`」にする)。
   Mandatory Rule 13 と Implementation Checklist も合わせる。
2. `pageHierarchy.ts`のノードに「メニューから開ける画面」の印(例: `menuEntry: true`)を足し、`useBackTarget`は、
   遷移元の記録が無いときに印の付いた画面では親へのフォールバックをしない(戻るリンクを出さない)。
   画面名・親(サイドバーの点灯・タブ名に使う)は変えない。対象: 日次`/attendance/days/:date`・月次`/attendance/months/:yearMonth`
   (週次・ホームなど親を持たない第1階層は元々出ない)。
3. 勤怠の切り替えリンク2か所(日次→「週次」、週次→「月次勤怠」)から`state`を外す。掘り下げ(日の行・ホーム・月の一覧・月次の週の警告)は変えない。
   週次画面の左上に`BackLink`を置く(週次は親を持たないので、掘り下げで来たときだけ出る)。
4. 月次画面の月送りの並びに「月の一覧」リンク(`/attendance/months`)を置き、戻るリンクが出ているときは出さない。
5. 点検結果の「切り替え」7か所から`state`を外す(勤怠の2か所は3.と同じ)。
6. 掘り下げの行き先になっている第1階層の画面(週次・有給・特別休暇・代休)に`BackLink`を置く。§2.26-2の「第1階層には置かない」を
   「第1階層は親を持たないため、掘り下げで来たときだけ出る。掘り下げの行き先になる第1階層の画面には置く」に改める。

## 受け入れ条件

- 論点2の表のとおりに戻るリンクが出る/出ない。
- 月次画面から月の一覧へ行ける。
- 掘り下げで来た日次で前日/翌日に動いても戻るリンクが保たれる。

## 対象外

- 戻り先の解決順・入れ子の記録(5段)・キャンセル/削除後の遷移の規則(§2.26-3〜4)は変えない。
- 保存後の遷移先。
