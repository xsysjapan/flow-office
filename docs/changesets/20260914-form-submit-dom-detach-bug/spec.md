# フォーム送信ボタンがクリック中にDOMから外れる不具合の調査記録

ステータス: 検討中

## 変更要望(原文)

> (E2E調査の過程で発見。ユーザーへの報告)「scenario-14の`作成`ボタンをクリックしようと
> した際、要素がDOMから外れて再試行し続ける」不具合について、対応要否を確認したところ
> 「別の対応で行いたいので、変更ドキュメントの作成だけお願いします」との回答。

## 背景・目的

`docs/changesets/20260914-port-to-pr112/`(有給休暇 付与Schedule/Assessmentドメインの
PR#112移植)のE2E原因切り分け作業中に、有給休暇ドメインとは無関係な既存の不具合を
偶然発見した。フルE2Eスイート実行時にscenario-14(備品管理)・scenario-13(外部連携)
以降のシナリオで多発していたログインタイムアウトの一部が、実はサーバー負荷や
ネットワーク環境要因だけでなく、**フォーム送信ボタンをクリックする際にボタン要素が
DOMから外れ、Playwrightがクリックを再試行し続けてタイムアウトする**という、
アプリケーション側の再レンダリング起因の不具合であることが判明した。

本changesetは、有給休暇ドメインの作業スコープ外であるため深追いせず、発見した事実を
記録するに留める。原因調査・修正は別タスクとして改めて着手する。

## 現状(As-Is)

### 観測された事象(2件、いずれもPlaywright E2E実行中)

1. **ログイン画面(モックOIDCログインボタン)**:
   `frontend/e2e/support/auth.ts`の`loginAs()`内、
   `page.getByRole('button', { name: 'Microsoftでログイン' }).click()`実行時に
   `element was detached from the DOM, retrying`が発生し、最終的に
   `page.waitForURL`が120秒でタイムアウト。フルE2Eスイート実行の後半(scenario-13
   以降)で複数回再現。単発では成功することもあり、当初はネットワーク・サーバー負荷の
   問題と誤認していた。
2. **備品登録画面の`作成`ボタン**(`frontend/e2e/scenario-14-asset-management.spec.ts`
   `registerAsset()`ヘルパー内、`getByRole('button', { name: '作成' })`クリック時):
   同じく`element was detached from the DOM, retrying`が発生し120秒でタイムアウト。
   **フルスイートだけでなく、`scenario-14-asset-management`を単独実行しても同様に
   再現**したため、サーバー負荷・並行実行の影響ではなく、アプリケーション側の
   再現性のある不具合であることを確認した。

### 共通点・推定される原因の方向性(未確定)

- 2件とも「別ドメインの画面(ログイン画面・備品登録フォーム)」かつ「フォーム送信の
  主ボタンをクリックする瞬間」に発生しており、個別ページの実装バグというより、
  レイアウト・フォーム・ボタン等の**共通コンポーネント、または送信時に発火する
  横断的な副作用(例: グローバルなロード状態管理・React Queryの再フェッチ・
  レイアウトの条件分岐レンダリング)** に起因する可能性が高い。
- 「detached from the DOM, retrying」はPlaywrightが「クリック対象の要素は最初
  resolveできたが、実際にクリックする直前に(Reactの再レンダリングで)その要素が
  DOMツリーから消えた」ことを示す標準メッセージであり、要素自体が見つからない
  (`waiting for selector`のまま)のとは異なる。ボタン押下と同時に親要素以上が
  丸ごと再マウントされるような処理が疑われる。
- 本changesetの調査時点では、実際のブラウザ画面のスクリーンショット・
  React DevTools等を使った再レンダリング箇所の特定until行っていない
  (Playwrightのtrace.zip・error-context.mdのテキストログのみで判断している)。
- 発生頻度: 単独実行での再現は確認したが、確率的なもの(毎回100%再現するか)は
  未検証。同じPlaywrightセッション内で1回でも成功した記録も過去にあるため
  (フルスイート実行のごく初期のログイン成功ケース)、常時100%再現ではなく
  タイミング依存の可能性がある。
