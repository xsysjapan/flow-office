## 背景・目的

`docs/delegation-reviews/`(2026-09-19〜10-15、123行)を集計すると、implementerの出力に実問題があった
45行のうち約13行は「委譲元の指示不足」が原因と委譲元自身が記録している。その是正は「以後〜する」という
ログ上のメモに留まり、ファイルに反映されていないため同種の不足が10-10→10-14→10-15と再発している。
委譲指示を組み立てる側(メインの会話)のチェックリストをファイル化し、毎回参照させる。

## 現状(As-Is)

- `.claude/agents/implementer.md`は受け手側の注意(シグネチャ・日付キャスト等)を蓄積しているが、
  送り手側(委譲元)が指示に含めるべき項目の定めはない(CLAUDE.mdは「対象ドメイン名・参照実装・スキル名を明示」のみ)。
- 定義は`model: haiku`だが、10-11以降implementerの約40行が呼び出し時にsonnetを指定。いつ上げるかの基準がファイルに無い。
  `delegation-review`はmodel列を定義と一致させる前提で、上げた理由が残っていない。

## 設計前提の検証

- 業務データ・コードには触れない(開発運用ドキュメントのみ)。

## 仕様検討

### 論点1: 指示不足の分類(ログから)
| 分類 | 例(ログ日付・内容) |
|---|---|
| 適用経路の限定・漏れ | 10-10 不足拒否を承認経路だけに適用する指示が無い / 10-14 「$convertedだけ」と書きpassThroughを想定せず / 10-15 「passThroughで差し替える」と経路を限定 |
| 欠落時・境界の扱い | 10-14 対応する旧版イベントが無いときの日時の取り方を書かなかった |
| 既存規則の網羅 | 10-14 現行の全規則(確定・付与・取消・変更)を当てはめる指示が初回に無く2回差し戻し |
| 命名・配置 | 10-10 新規クラス名の衝突未確認 / 10-10 複数文脈の同じ処理の置き場所を指示せず330行の複製 |
| DB・破壊的操作 | 10-10 新設Projectorのテーブルで既存Projectorが埋めるNOT NULL列 / 10-14 一覧から参照マスタを除く要件を指示せず |
| テストの前提・期待値 | 09-19 期待値をimplementerが組み立て捏造 / 10-14 シーダー再実行の前提・キューの実行方法を指示せず |
| モデル | 10-11 複雑な変換規則でhaikuが2回途中停止→sonnet |

### 論点2: チェックリストの置き場所
- 選択肢: A) CLAUDE.mdに直書き / B) implementer.mdに追記 / C) 委譲元用の新スキル`delegate-implementer`
- 決定: C(CLAUDE.mdの委譲の項から1行で参照)
- 理由: CLAUDE.mdは毎ターン読み込まれ肥大化させたくない。implementer.mdは受け手が読むもので、送り手の
  チェックには効かない(受け手は欠けていることに気づけない)。スキルなら委譲の直前に読み込める。

### 論点3: モデル選択の基準
- 決定: 既定はhaiku。(a) 複数の入力経路・既存規則と同じ結果を保証する変換/状態機械、(b) 同一タスクでhaikuが
  途中停止・同じ差し戻しを2回、のいずれかでsonnetに上げる。上げた場合はdelegation-reviewのmodel列に実際の
  モデル、対応列に理由を書く(`delegation-review`の記述も合わせて直す)。
- 理由: 10-11の振り返りの運用をファイル化する。

### 論点4: テスト実行
- 決定: 指示にテストの実行要否と対象を明記する項目だけ置く(ユーザー指示により実行の強制はしない)。

### 論点5: 受け手側の報告
- 決定: implementer.mdに「報告に変更ファイル一覧(`git status --short`)を含める」を追加。
- 理由: 無関係ファイル混入(09-19 composer.lock)・途中状態のコミット(10-14)を委譲元が報告だけで気づけるようにする。

## 仕様確定事項(まとめ)

1. 新規`.claude/skills/delegate-implementer/SKILL.md`: 委譲指示のテンプレートと、論点1の分類に沿った確認項目、モデル選択基準。
2. `CLAUDE.md`: implementerへの委譲の項に、指示はこのスキルで組み立てる旨を1文追加。
3. `.claude/agents/implementer.md`: 報告に`git status --short`を含める。
4. `.claude/skills/delegation-review/SKILL.md`: model列は実際に動いたモデル、定義と違う場合は理由を対応列へ。
