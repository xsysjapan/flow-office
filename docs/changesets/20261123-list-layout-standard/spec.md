### 論点2: 画面の見出し
- 選択肢:
  - A. 全画面にページ見出し(h1)の共通部品を置く
  - B. 管理画面だけページ見出し(画面名+説明文)を置き、管理画面以外はページ見出しを置かず Card の見出しで画面名を示す
  - C. 現状のまま
- 決定: B(ユーザー回答「管理画面は見出しに説明を用意して、管理画面以外は基本的に見出しを用意しない」)
- 細則:
  - 画面名の出典は `routes/pageHierarchy.ts` の title(ブラウザのタブ名と同じ。管理の一覧はナビの label がそのまま title)。動的な title(「{n}月{d}日の勤怠」等)もそのまま使う。
  - **管理画面(`/admin` 配下の全ルート)**: 新しい共通部品 `PageHeader`(`components/PageHeader/`)を本文の先頭(戻るリンクがある画面は戻るリンクの下)に置く。
    - props: `title`(省略時は現在のルートの `pageHierarchy` の title)、`description`(必須。下の表B の文)、`actions?`(画面全体の操作。右寄せ。`md` 未満は見出しの下に回り込む)、`meta?`(状態のバッジ・期間など。見出しの横)。
    - 見出しは h1(`text-lg font-semibold text-foreground`。既存の管理7画面と同じ)、説明は `text-sm text-muted-foreground`。直書きの h1 はすべて `PageHeader` に置き換える。
    - Card の見出しはセクション名だけにし、`PageHeader` の title と同じ語にしない。Card が1つだけの画面は、その Card の title を外す(重複を避ける)。
    - 画面全体の操作(新規作成・CSV・関連画面への移動・会社カレンダーの「デフォルトに設定する」・年度の「休日と同期する」「公開する」)は `PageHeader` の actions に置く。セクションの操作は Card の actions のまま。
  - **管理画面以外**: ページ見出しは置かない。画面の主となる Card(先頭の Card)の title を画面名にする。Card が複数の画面は、2つ目以降の Card の title をセクション名にする。主操作は先頭の Card の actions。
  - 戻るリンク(`BackLink`)の位置・文言は変えない(§2.26)。

### 論点3: 主操作(新規作成など)と、その他の画面操作
- 決定:
  - 置き場所: 管理画面は `PageHeader` の actions、管理画面以外は主となる Card の actions。主操作は右端に primary の Button で1つ。その他の画面操作(CSV・関連画面への移動)は主操作の左に secondary の Button(テキストリンクにしない)。
  - 文言: 「新規作成」に統一する(ユーザー回答)。業務用語の例外は残す: 申請一覧の「新規申請」(遷移先の画面名)、API・MCP連携と外部連携設定の「新規登録」(docs/25 の業務用語。Pattern exception を記録済み/外部連携設定は記録を足す)。
  - 変更する画面: 備品「新規登録」(`size="sm"` も外す)→「新規作成」、端末「新規登録」→「新規作成」、グループ「新規グループ」(テキストリンク)→ primary の Button「新規作成」、所属変更「変更予約作成」→「新規作成」、
    社員一覧の本文の「ユーザーを作成」→ `PageHeader` の actions の「新規作成」。社員一覧の「外部ID・HR連携」(リンク)・有給休暇の付与予定へのリンク → secondary の Button。
  - 備品の本文にある一括操作へのリンク群(セルフ一括貸出・セルフ一括返却・一括貸与・一括返却・一括移設、`AssetListPage.tsx:191-200`)は、Card の actions の secondary の DropdownMenu「一括操作」にまとめる(主操作「新規作成」の左)。
  - インラインのフォームを開閉するトグル(社員一覧・端末・外部連携設定・API・MCP連携): 閉じているときは上の文言、開いているときは「閉じる」(secondary)に揃える(社員一覧の「キャンセル」→「閉じる」)。フォームは本文の先頭(PageHeader/Card ヘッダーの直下)に開く。
    インラインで作成すること自体の見直し(§2.11)は、フォームの変更セットの論点8(別の変更セットの候補)に加える。
  - 空状態の作成ボタンも同じ文言(「新規作成」)。同じ名前のボタンが2つになるため、e2e は Card の actions/PageHeader の中に絞って押す。
- 理由: 現状の多数派で、§2.7(作成)に合う。業務用語は遷移先の画面名・仕様書と一致させる。

### 論点5: ページング

### 論点6: 詳細条件(要否と見せ方)
- 要否: 直接表示は4項目まで、超える分を詳細条件にする(§2.20 現行を維持)。理由: 備品・監査ログ・社員は全表示すると表より検索欄が大きくなる。Sheet は結果を見ながら変えられない。
- 見せ方(R3・R5・R6・R10): 
  - `ListFilterBar` の末尾のボタン(「詳細条件」「検索条件をクリア」)は1つのまとまり(`flex gap-2`)にし、項目の後ろに `ml-auto` で置く(折り返すときはまとまりごと次の行の右端へ。ボタンが1つずつ取り残されない)。
    クリアボタンが条件の入力で現れたときにまとまりが次の行に落ちて表が下がることは許容する。
  - 「詳細条件」は `variant="secondary"` にし、開閉のアイコン(lucide の ChevronDown/ChevronUp)を付ける。件数表示「詳細条件(n)」は現行どおり。
  - 詳細条件の領域はフィルターバーの下の枠付きの面(`rounded-md border bg-muted/40 p-3`)。中は等幅のグリッド(`grid grid-cols-1 gap-3 @md:grid-cols-2 @3xl:grid-cols-3 [&>*]:mb-0`)。項目の幅はグリッドに任せる(`filterWidth` を使わない)。
- 未確定・要確認事項: なし

### 論点7: 狭い本文幅での項目の幅(R4)
- 決定: フィルターバーをコンテナ(`@container`)にし、項目の幅を本文の幅で決める(Tailwind v4.3.2 のコンテナクエリ。既定の区切り値 @md=28rem・@3xl=48rem)。
  `filterWidth` を `keyword: 'w-full @md:w-72'`、`select: 'w-full @md:w-44'`、`yearMonth: 'w-full @md:w-48'`、`dateRange: 'w-full @md:w-72'` にする(フィルターバーが 28rem 未満なら全項目が全幅で縦に並ぶ)。
  申請一覧の種別は `filterWidth.select`。端末のチェックボックス行は `h-9`。
- 理由: 管理画面は管理メニューの分だけ本文が狭く、画面幅では本文の幅が分からない。区切りを @md にすると、幅768(管理メニューを畳んだ後の本文 約454px)でも横に並ぶ。
- 未確定・要確認事項: なし

### 論点8: 狭い幅の表示
- 主軸タブ(R1・P1): 折り返して全タブを見せる(`ListQueueTabs` の TabsList を `h-auto flex-wrap`、`max-w-full` は残す、`overflow-x-auto` をやめる)。2行になると背景の面が矩形に広がり最終行が左詰めになる見た目を許容する。
  前の変更セット論点3と §2.20 の「モバイルは横スクロール」を覆し、§2.20 の該当文を書き換える。理由: 横スクロールでは続きのタブと件数が見えない(R1)。
- 表(P4): 横スクロールのまま、件名などの長い文字列の列だけ折り返す。`ui/table` の一律 `whitespace-nowrap` は残し、次の列に `whitespace-normal min-w-48` を付ける:
  申請一覧・承認一覧・タスク一覧・経費精算の「タイトル」、入力プリセット・備品・端末の「名称」、付与予定の「社員」は対象外(短い)。監査ログのイベント種別などの識別子は `break-all`(P2)。
  理由: カード型は全画面分の別表示が要り費用が大きい。列を隠すと必要な情報が見えない。
- 管理画面の本文幅(P3): 管理メニューの縦のサイドバーは `xl`(1280px)以上だけに出し、未満は今 `sm` 未満で使っているメニューボタン(Sheet)を使う。`AdminLayout.tsx` の `sm:flex-row`(:88)→`xl:flex-row`、`sm:hidden`(:89)→`xl:hidden`、`hidden sm:block`(:111)→`hidden xl:block`。
  理由: 1024px でもアプリのサイドバーと並ぶと本文が約446pxで、768より狭い。1280 では本文 約702px。
- 期間の入力(R2): `DateRangePicker` の表示 span に `min-w-0`(`truncate` は既にある)。
- 未確定・要確認事項: なし

### 論点9: 空状態(P6)
- 決定: 一覧の空状態は `components/EmptyState` で出し、2種に揃える。§2.17 の例文も合わせて直す。
  - Initial(まだ無い): 見出し「{対象}はまだありません。」。主操作がある画面で、操作できる人には説明「{主操作の文言}から{対象}を作成できます。」と主操作と同じボタン。
  - Filtered(条件に一致しない): 見出し「条件に一致する{対象}はありません。」+説明「検索条件を変えると表示される場合があります。」+[検索条件をクリア]。
  - 主軸タブのタブごとの Initial 文言は §2.20 のとおり。端末の「削除済みの端末も表示」は件数が減らないため Filtered を使わない(現行どおり)。
- 対象(文言・ボタンを直す画面): 付与予定(Filtered に説明が無い)、社員一覧(説明「検索条件を変更するか、…」を標準文に)、グループ(Filtered の説明が無い場合)、ほか実装時に `EmptyState` の title・description・action を一覧に書き出し、上の2種に合わないものを全て直す(実装結果に一覧を載せる)。
- 未確定・要確認事項: なし
