# E2E全件実行で見つかった失敗(今回の変更起因・既存不具合)をすべて直す

ステータス: 実装中

## 変更要望(原文)
> 全て対応したらE2Eテストも実施してデグレってないことを確認してください。
> 既存の不具合も含めて全部直してください

## 背景
PR #132(一覧・操作のフィードバック標準化)の確認としてE2E(69件、1 worker、DB共有)を全件実行したところ、
16件以上が失敗した。原因を調査した結果、今回の変更起因は1件のみで、残りは既存のアプリ不具合1件と、
テスト側の不備(先行specの後始末漏れによる残留・古いラベル・待ち合わせ不備・共有DBに弱い期待)だった。

## 原因と修正方針

| # | 失敗 | 原因 | 分類 | 修正 |
|---|---|---|---|---|
| 1 | scenario-06 §5-11 打刻ログの削除 | 削除理由の入力を確認ダイアログへ移した(標準化) | 今回の変更 | specをダイアログ操作に合わせる(`getByRole('dialog', {name:'打刻を削除しますか?'})`内で削除理由入力→「削除する」) |
| 2 | scenario-14 備品管理(登録を含む7件) | `GET /asset-number-rules/categories`は`{data:[...]}`を返すが`fetchAssetNumberRuleCategories`は`string[]`として扱い、`CategoryCombobox`で`suggestions.filter is not a function`のクラッシュ | 既存のアプリ不具合 | `frontend/src/api/assetNumberRules.ts`で`.then((res) => res.data)`とunwrap(`api/paidLeave.ts`等の慣例)。API関数のテストを追加し実レスポンス形状を検証する |
| 3 | scenario-99 §5-1〜§5-4・§5-8・§5-19 ほか、高橋 健太でログイン不可 | scenario-11「外部HR管理項目…」(:742)が高橋を`disabled`→`retired`にして戻していない | テスト(残留) | 同テストを`try/finally`にし、finallyで`account_status: "active"`へ戻す(勤怠履歴が保持されることの検証は高橋のまま行う) |
| 4 | scenario-15:49 人事担当者が`/admin/paid-leave`へ入れない | scenario-11「直接Role付与…」(:330)が加藤のhr_staff割当(本人・HUMAN_RESOURCES_USERSグループ分)をDELETEし戻していない | テスト(残留) | 削除した割当を記録し、finallyで同じrole/scope/対象で再作成する |
| 5 | scenario-11 その他の残留 | 伊藤の`administration` Feature停止(:248)、E2E_SCOPE_*グループ所属 | テスト(残留) | Feature停止はfinallyで`DELETE /feature-suspensions/{id}`。所属は後続への影響がないため対象外 |
| 6 | scenario-99 §5-6+7 | 管理ナビのリンク名「付与ポリシー」は現在「有給休暇」(既存記録あり) | テスト(古いラベル) | ラベルを「有給休暇」に合わせる |

| 9 | scenario-09 §5-17 | 期待文言「締め処理済みのため修正できません…」はアプリにも仕様(docs/11 UC-B007)にも存在しない | テスト(未定義の期待) | 既存UI(「締め済み」ステータスと日別の内訳)を確認する期待に置き換える |

## 決定事項
- アプリの修正は#2のみ。他はテスト側の修正で、アプリの仕様は変えない。
- #9は「注記を新たに表示する」案もあるが、仕様化されておらず今回の範囲外とする(締め済みバッジで状態は分かる)。
- #7の、退職者の承認済み月が送信対象に含まれる点は仕様判断のため対象外(docs/33どおり)。
- 残留の解消は「各テストが自分で変えた状態を戻す」方針に統一する(既存慣例: scenario-11:195 のfinally)。

## 対象外
- 退職者の外部送信対象の扱い、締め済み注記の新設。

## ドキュメントへの影響
- なし(テストとAPIクライアントの修正のみ)。

## テスト
- vitest: `api/assetNumberRules`の実形状テスト、関連ページテスト。
- E2E: 失敗したspecを個別に再実行し、最後に全件を再実行する。
